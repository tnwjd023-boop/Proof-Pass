# Gate 1 바인딩 기반 XRPL 자격·상태 관측

Spec: `ProofPass_기획서_v2.md` 6·10·12·18절 및 기존 바인딩 설계. 기존 자율 진행 요청에 따라 직접 구현한다.

Goal: 실제 바인딩 서명을 검사한 뒤 Credential을 발급·수락하고, 최신 validated 상태로만 짧은 관측 lease를 생성한다. 아직 Compact 서명과 목적지 반영까지 완료했다고 주장하지 않는다.

Design: issuer는 고정 adapter public key/audience/issuer policy/네트워크를 신뢰한다. caller의 public key나 verified boolean은 받지 않는다. 신규 발급의 Expiration은 바인딩 근거 만료와 1시간 중 이른 값이다. observer는 ledger hash에 고정한 조회만 사용한다. 객체 부재와 RPC 실패는 구분하고 둘 다 신규 허용을 만들지 않는다. sourceEpoch는 관측 상태·credential 세대가 바뀔 때 증가하고 restart 이후에도 유지한다. 공개 증거에 두 체인 지갑 연결을 기록하지 않는다.

Review focus: 서명키 치환; 만료/다른 audience 바인딩; 미수락/만료 credential; stale 또는 같은 index의 상충 ledger; 삭제·재발급 이후 이전 epoch 부활; 실패 RPC를 absent로 기록하지 않기.

1. `src/binding/attestation.mjs` / `test/credential-policy.test.mjs`: 서명 검증·정책/대상/time 검사. RED→GREEN.
2. `src/xrpl/observer.mjs` / `test/credential-policy.test.mjs`: accepted/absent/unaccepted/expired 상태와 최대60초 lease; ledger 단조성 및 generation fingerprint epoch. RED→GREEN.
3. `src/xrpl/lifecycle.mjs`: Testnet 검증, durable signed intent, 기존 hash 조회, 동일 blob 재전송만 허용. create/accept/delete 이후 ledger 객체 확인.
4. `scripts/gate1/credential-demo.mjs`: 실제 바인딩 생성→서명 확인→create→미수락 거절→accept→관측 허용→delete→관측 거절, 실행 증거와 상태 문서. 전체 회귀 검사와 독립 검토.

체인 거래는 기존 프로젝트 전용 테스트 issuer/subject만 사용하고 별도 journal을 쓴다. 기존 Gate0 증거는 유지한다. Config·키 파일은 `.local` 내부의 운영자 자료다. test fixture의 임의 값을 외부 입력의 신뢰 근거로 사용하지 않는다.
