# ProofPass Gate 0 실행 계획

> 후속 작업자: 기획서와 COMPATIBILITY.md를 먼저 읽고 확인된 상태에서 이어간다. 구현 단계에는 superpowers:executing-plans를 적용한다.

**Goal:** 네 구성요소가 실제 실행 가능한지 검증하고 실패 원인까지 기록한다.

**Architecture:** 각 공식 SDK·예제를 독립 검증한 뒤 가장 얇은 결제 경로를 연결한다. 이번 계획의 범위는 Gate 0이며 본 제품 회로·결제 프로그램의 전체 구현 계획은 Gate 0 결과를 반영해 작성한다.

**Tech Stack:** 사용자가 선택한 WSL2 + Ubuntu, Java 21, Node 22, 고정된 OpenDID SDK와 Midnight 예제, XRPL Testnet, Solana Devnet.

**Spec:** `ProofPass_기획서_v2.md` 16·18절. 버전·현재 상태는 `COMPATIBILITY.md`, 소스 commit은 `config/upstream-lock.json`.

## Global Constraints

- 원본 신원정보·전체 위임 한도·개인키·seed·private witness를 공개 증거에 기록하지 않는다.
- 테스트 발급자, XRPL Testnet, Solana Devnet을 사용한다.
- 거래 승인서는 요청별 일회용이며 거래당 한도만 다룬다.
- UI는 Gate 0 이후에 다룬다. Transfer Hook·실제 LLM·누적 예산은 제외한다.
- mock, API 응답, 로컬 실행, 네트워크 확정을 구분한다.

## Review Focus

1. 설치 exit 0인데 Ubuntu가 실행되지 않는 경우: `wsl -l -v`와 Linux 명령 실행까지 확인.
2. 공식 SDK에 실제 테스트가 없는 경우: `NO-SOURCE`를 성공으로 취급하지 않고 실제 발급·검증 표본 요구.
3. XRPL 발급만 성공하고 미수락인 경우: validated ledger의 accepted 플래그까지 확인.
4. Midnight 서명만 맞고 사용자 바인딩이 잘못된 경우: 기존 사용자 간 서명 재사용 테스트 포함.
5. Solana RPC만 연결되거나 지갑 간 송금만 된 경우: 배포된 프로그램의 vault 지급을 별도 확인.

## 과거 재개 기록 (2026-09-20 20시 KST)
