# 3분 발표 대본

화면에 표시된 완료 시각과 함께 **이미 수행한 실제 실행의 기록을 설명한다**고 먼저 말합니다. 실시간 실행을 보여줄 때는 버튼을 누른 시점부터 기록하며, 대기 시간을 편집했다면 영상에 표시합니다. 화면에 과거 실행이 남아 있는 동안 새 실행 성공이라고 말하지 않습니다.

제공된 [발표용 영상 플레이어](../evidence/demo/watch.html)는 실제 전체 실행 원본을 순서 변경 없이 **1.4배속**으로 재생합니다. 원본은 약 4분이며 발표용은 3분 이내입니다. 두 영상 모두 내레이션은 없고 아래 대본으로 설명할 수 있습니다.

| 시간 | 화면 | 발표 |
|---|---|---|
| 0:00–0:20 | 상단 요청 | “자격 증명만 복사한다고 다른 체인의 에이전트에게 거래 권한이 생기지는 않습니다. 현재 자격, 같은 사용자의 지갑, 그리고 이 거래에 대한 위임을 함께 확인해야 합니다.” |
| 0:20–0:45 | Identity | “합성 신원의 테스트 자격을 실제 OpenDID SDK로 검증했습니다. nonce에 세션을 묶고 XRPL과 Solana 지갑의 실제 서명을 확인합니다. 모바일 지갑 통합 데모는 아닙니다.” |
| 0:45–1:10 | XRPL, 발급·수락 링크 | “XRPL Testnet에서 자격을 발급하고 수락했습니다. 관측자는 validated ledger에서 자격의 발급자·소유자·종류와 유효기간을 대조합니다.” |
| 1:10–1:50 | Midnight, Solana, 지급 링크 | “사용자가 서명한 위임과 현재 자격을 실제 로컬 Midnight 회로가 검증합니다. relay가 정확한 요청을 목적지에 등록하면 Solana 프로그램이 다시 권한을 검사하고 0.05 test SOL을 한 번 지급합니다.” |
| 1:50–2:10 | 동일 승인 재사용 거절 | “같은 승인서는 consumed 처리되어 다시 사용할 수 없습니다. 실제 거절 거래에서 추가 지급이 없음을 확인했습니다.” |
| 2:10–2:35 | 로컬 위임 한도, 한도 초과 결과 | “사용자 위임 한도는 0.10 SOL입니다. 0.15 SOL 요청은 회로의 승인 생성 단계에서 거절됐습니다. 실패 proof가 체인에 기록됐다고 주장하지 않습니다.” |
| 2:35–3:00 | 자격 삭제, 측정값 | “자격을 삭제하고 목적지의 상태 epoch를 갱신했습니다. 만료 전 남아 있던 승인도 거절됐습니다. 이 실행의 삭제 확정 후 반영 시간은 화면의 실측값이며, 즉시·원자적 취소를 보장하지 않습니다.” |

마무리: “ProofPass는 자격 자체를 공개하는 대신 필요한 조건을 검증하고, 실제 지급 프로그램이 그 결과와 현재 권한을 따르도록 연결합니다.”

## 질문에 대한 짧은 답

- **무신뢰 브리지인가요?** 현재는 아닙니다. 검증 어댑터·시각 제공자·relay의 신뢰를 명시한 프로토타입입니다.
- **정말 체인에서 지급되나요?** Solana Devnet 프로그램에서 실제 lamports를 이동했습니다. 거래 링크와 원거래 잔액 변화가 증거입니다.
- **비공개 데이터가 어디로 가나요?** 로컬 prover와 어댑터가 처리합니다. 공개 거래 참조와 시각의 상관관계까지 숨기지는 않습니다.
- **삭제 즉시 막히나요?** 관측과 목적지 반영 지연이 있습니다. 반영 후 신규 승인과 남은 승인 사용을 차단하는 범위를 검증했습니다.
